API Style Guide

Super uses one short canonical name for one concept. Receiver context avoids stutter: users.len(), app.get(...), and map.get(key).

  • Use snake_case values/functions and UpperCamelCase types/variants.
  • Use verbs for actions and nouns or adjectives for values and predicates.
  • Let types constrain meaning: len(text) and len(items), never type-prefixed duplicates.
  • Canonical collection operations are len, get, and contains.
  • Scope methods to their owning type. Use macros only for syntax, source capture, item generation, or comptime structure.
  • Do not hide allocation, blocking I/O, global mutation, or unrelated linear work behind a cheap-looking accessor.
  • Callback APIs statically constrain arity and return types; runtimes never silently discard callback values.

During 0.x, canonical APIs may change in a breaking release. Complete each rename across compiler, stdlib, examples, tests, book, specification, site, agent text, and editor tooling. Do not retain aliases or shims.
