# Contributing to Super

Public norms for https://github.com/theHamdiz/super-lang.

## Setup

```bash
# one-liner (→ ~/.super) or from a checkout:
./scripts/install.sh   # make install
cargo test --workspace
```

Needs a recent stable Rust (edition 2024). Stdlib is **only** `stdlib/**/*.sr`; host builtins belong in `crates/super-host`.

## API Style Guide

Super APIs should read as direct operations on values. Prefer one short,
canonical name for one concept across the compiler, standard library, examples,
and documentation.

### Names

- Use `snake_case` for values and functions, `UpperCamelCase` for types and sum
  variants, and clear nouns for constants.
- Avoid stutter. A method already has its receiver for context:
  `users.len()`, not `users.user_count()`; `app.get(...)`, not
  `app.app_get_route(...)`.
- Use verbs for actions (`send`, `serve`, `close`) and nouns or adjectives for
  values and predicates (`name`, `empty`, `ready`).
- Let types constrain meaning instead of encoding types in names. Use
  `len(text)` and `len(items)` instead of type-prefixed length helpers.
- Scope methods to the type that owns the operation. Use a free function only
  when there is no natural receiver or when the operation intentionally spans
  unrelated types.

| Concept | Canonical name | Avoid |
|---|---|---|
| Number of elements or bytes defined by the type | `len` | type-prefixed length variants, `count_items` |
| Lookup by key or index | `get` | `get_value`, `lookup_item`, `map_get` |
| Membership test | `contains` | `has_item`, `includes`, `contains_key` when the receiver already fixes key semantics |

### Functions, methods, and macros

- Use an ordinary function or method when runtime values are sufficient.
- Use a macro only when syntax, source capture, item generation, or comptime
  structure is essential. A macro must document evaluation count and generated
  behavior.
- Do not hide allocation, blocking I/O, global mutation, or work proportional
  to unrelated state behind a cheap-looking accessor. Name and document costs;
  measure allocations with a counting allocator before claiming a path allocates nothing.
- Callback and registration APIs must statically constrain arity and return
  types. Never accept a value that the runtime silently discards.

### Compatibility during 0.x

Before 1.0, a better canonical API may replace a weak one in a breaking
release. Complete the rename in one change: compiler, stdlib, examples, tests,
book, specification, site, agent text, and editor tooling. Do not retain
deprecated aliases, shims, or parallel spellings. “One concept, one name” is
the compatibility policy for this stage.

## Commits / PRs

- Short imperative subjects; explain **why**.
- No vendor/tool `Co-authored-by` trailers or “generated by …” spam in commits, PRs, or releases.
- No secrets, `.env`, private keys, local agent dumps, or private plans (keep those in `.local/`).
- Pair behavior changes with tests (`crates/*/tests` or `test` blocks in `.sr`).

## Good first issues

Concrete starter tasks (pick one PR; mention the bullet in your PR description).

1. **`scripts/check_windows_aot_net.py`** — Add a unit test under `scripts/test_check_windows_aot_net.py` that feeds temp files with banned Tier-1 Windows networking phrases and expects exit 1.
2. **`docs/platform.md`** — When Tier columns change, update `scripts/generate_facts.py` row parser and add an assertion in `scripts/test_generate_facts.py` for `aot_sockets` on the Windows row.
3. **`crates/super-frontend/src/sema.rs`** — Add one negative `E0402` test for array slice escape; mirror an existing `*_ok` positive in the same module.
4. **`stdlib/core/str.sr`** — Add a `test` block for `char_count` on an ASCII edge case; no law file required if none exists.
5. **`examples/00_hello_api`** — Add a `test` for `405` on wrong HTTP method; run `super test examples/00_hello_api`.
6. **`editors/vscode/package.json`** — Bump displayed version to match workspace `0.1.0` if drifted; smoke-load in VS Code.
7. **`scripts/check_links.sh`** — Extend internal link scan to include new governance pages (`safety-claims`, `reproduce-benchmarks`).
8. **`crates/super-lsp/src/lib.rs`** — Wire one additional `super-lint` rule id into LSP `code` field; add `crates/super-lsp/tests/lint_diagnostic.rs`.
9. **`stdlib/fmt/json.sr`** — Add law-sidecar comment cross-link in module header only if missing paired `test` (B8); add the `test` if absent.
10. **`docs/VERIFYING_RELEASES.md`** — Document actual `SHA256SUMS` filename layout from `.github/workflows/release-bundle.yml` once confirmed in workflow.
11. **`benchmarks/test_runner_smoke.py`** — Add a test that `--rescore` never mutates `data/results.json` bytes (read-only check).
12. **`crates/super-cli/tests/alloc_probe.rs`** — Gate probe with `#[cfg(target_os = "linux")]` comment explaining why; document in `docs/http-server.md`.
